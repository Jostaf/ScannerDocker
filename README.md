# Docker Net Profiler

CLI-инструмент на Python для мониторинга активности Docker-контейнеров. Программа собирает информацию о контейнерах, анализирует сетевую активность и помогает обнаруживать контейнеры, которые простаивают в течение заданного времени.

## Возможности

- Получение информации о Docker-контейнерах через Docker SDK.
- Сбор сетевых счётчиков RX/TX для каждого контейнера.
- Определение сетевой активности на основе изменения счётчиков.
- Обнаружение неактивных контейнеров по заданному тайм-ауту.
- Получение сетевых соединений хоста с помощью psutil.
- Фильтрация TCP- и UDP-соединений по PID процессов.
- Формирование отчётов в четырёх форматах:
  - Console
  - JSON
  - Markdown
  - HTML

## Установка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd ScannerDocker
```

### 2. Создание виртуального окружения

Для macOS, Linux и Windows:

```bash
python -m venv .venv
```

Если в Windows команда `python` недоступна, попробуйте `py`:

```powershell
py -m venv .venv
```

### 3. Активация виртуального окружения

**macOS / Linux (Terminal):**

```bash
source .venv/bin/activate
```

**Windows (PowerShell):**

```powershell
.venv\Scripts\Activate.ps1
```

**Windows (Command Prompt):**

```cmd
.venv\Scripts\activate.bat
```

Если PowerShell запрещает выполнение скрипта активации, можно временно разрешить его для текущего окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

После этого повторите команду активации.

### 4. Установка зависимостей

После активации виртуального окружения выполните:

```bash
pip install -r requirements.txt
```

## Запуск

Все команды запуска выполняются из корневой папки проекта при активированном виртуальном окружении.

### Обычный запуск

```bash
python -m docker_net_profiler.cli
```

### Однократный запуск

Собирает информацию о контейнерах один раз и завершает работу:

```bash
python -m docker_net_profiler.cli --once
```

### Параметры командной строки

| Параметр | По умолчанию | Описание |
|---|---:|---|
| `--interval` | 10 | Интервал между проверками в секундах |
| `--idle-timeout` | 30 | Время без сетевой активности в минутах |
| `--once` | — | Выполнить один цикл мониторинга |
| `--format` | console | Формат отчёта |
| `--output` | — | Путь для сохранения отчёта |

### Примеры запуска

Мониторинг с интервалом 5 секунд и тайм-аутом простоя 1 минута:

```bash
python -m docker_net_profiler.cli --interval 5 --idle-timeout 1
```

Создание JSON-отчёта:

```bash
python -m docker_net_profiler.cli --once --format json --output report.json
```

Создание Markdown-отчёта:

```bash
python -m docker_net_profiler.cli --once --format markdown --output report.md
```

Создание HTML-отчёта:

```bash
python -m docker_net_profiler.cli --once --format html --output report.html
```

Доступные форматы: `console`, `json`, `markdown`, `html`.

При непрерывном мониторинге JSON- и Markdown-отчёты обновляются по мере выполнения циклов. HTML-отчёт поддерживает автоматическое обновление страницы в режиме непрерывного мониторинга.

## Принцип работы

### 1. Сбор информации

Для получения информации о контейнерах используется Docker SDK.

Программа собирает:
- ID и имя контейнера;
- статус;
- PID основного процесса;
- используемый Docker-образ;
- дату создания;
- IP-адреса;
- опубликованные порты;
- сетевые счётчики RX/TX.

Сетевые счётчики получаются через Docker Stats API.

### 2. Анализ активности

Для определения активности программа сравнивает сетевые счётчики между последовательными снимками.

| Состояние | Описание |
|---|---|
| `OBSERVING` | Получен первый снимок или анализ начат заново |
| `ACTIVE` | Обнаружено увеличение RX или TX |
| `INACTIVE` | Счётчики не изменяются в течение заданного тайм-аута |
| `STOPPED` | Контейнер остановлен |
| `UNKNOWN` | Недостаточно данных для определения активности |

При обнаружении сетевой активности таймер простоя сбрасывается.

### 3. Сбор и фильтрация соединений

Для получения сетевых соединений хоста используется библиотека psutil.

Фильтрация выполняется по следующим правилам:

- PID соединения должен соответствовать PID процесса контейнера или одного из его дочерних процессов.
- TCP-соединения учитываются только в состоянии `ESTABLISHED`.
- UDP-соединения учитываются при наличии удалённого адреса.
- Остальные соединения отбрасываются.

Если определить соединения невозможно, программа показывает `-`, а не `0`.

Это позволяет различать две ситуации:
- `0` — соединения успешно проверены, но не обнаружены.
- `-` — получить достоверное количество соединений не удалось.

## Поддержка платформ

Основная функциональность приложения рассчитана на macOS, Linux и Windows.

| Возможность | macOS | Linux | Windows |
|---|---|---|---|
| Подключение к Docker | Да | Да | Да |
| Получение информации о контейнерах | Да | Да | Да |
| Сбор RX/TX | Да | Да | Да |
| Анализ активности | Да | Да | Да |
| Формирование отчётов | Да | Да | Да |
| Сопоставление PID и соединений | Нет для Docker Desktop | Best effort | Не гарантируется |

### Особенности Docker Desktop

В macOS и Windows Docker Desktop запускает Linux-контейнеры внутри виртуализированной среды.

Поэтому PID контейнера не соответствует PID процесса хостовой операционной системы.

В таких конфигурациях программа не может надёжно сопоставить сетевые соединения с контейнерами. Количество соединений отображается как неизвестное (`-`).

На Linux с нативным Docker Engine сопоставление PID может работать, но зависит от конфигурации PID namespace и прав доступа.

При этом сбор RX/TX через Docker Stats API и определение активности контейнеров продолжают работать независимо от сопоставления PID.

Поддержка Windows Containers отдельно не гарантируется.

## Тестирование

Для запуска тестов выполните команду из корневой папки проекта:

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют:
- определение активности контейнеров;
- переходы между состояниями;
- обработку сетевых счётчиков;
- фильтрацию сетевых соединений.
